# 🧪 Quality Lab — Ejercicio Día 10
## Persistencia real con PostgreSQL usando Testcontainers

### ⏱️ Duración estimada
90–120 minutos

### 🧪 Tipo de tests
- Tests de integración
- Spring Boot
- JPA / Hibernate
- PostgreSQL real
- Testcontainers
- Sin mocks

---

## 🎯 Objetivo del ejercicio

El objetivo de este ejercicio es aprender a:

- Ejecutar **tests de integración contra una base de datos real**
- Usar **Testcontainers** para levantar PostgreSQL bajo demanda
- Eliminar dependencias de entornos locales
- Tener tests:
    - reproducibles
    - aislados
    - cercanos a producción

---

## 🧩 Contexto

Hasta ahora:

- Has usado H2 para integración
- Has validado el wiring completo de la aplicación
- Has separado correctamente:
    - dominio
    - aplicación
    - infraestructura
    - web

Ahora el siguiente paso es **probar el sistema contra PostgreSQL real**, sin instalar nada en tu máquina.

---

## 🧩 Nuevo requisito técnico

Ejecutar los tests de integración usando **PostgreSQL real** levantado con Testcontainers.

---

## 📐 Reglas de diseño (muy importantes)

- ❌ No usar H2 en estos tests
- ❌ No usar mocks
- ❌ No cambiar la lógica de negocio
- ❌ No acoplar código de producción a Testcontainers

- ✅ Testcontainers solo vive en tests
- ✅ La app se configura dinámicamente desde el test
- ✅ La base de datos se crea y destruye automáticamente

---

## 🧪 Tareas a realizar

### A) Configurar Testcontainers

- Añadir dependencias necesarias
- Crear un contenedor PostgreSQL para tests
- Definir:
    - nombre de la base de datos
    - usuario
    - password

---

### B) Conectar Spring Boot al contenedor

- Configurar dinámicamente:
    - `spring.datasource.url`
    - `spring.datasource.username`
    - `spring.datasource.password`
- Evitar usar `application.yml` para esta configuración

---

### C) Ejecutar tests de integración reales

Usar los mismos casos de uso ya existentes para:

1. Crear una tarea
2. Finalizar una tarea
3. Manejar errores reales:
    - tarea inexistente
    - tarea ya finalizada

Estos tests deben:
- Arrancar PostgreSQL real
- Persistir datos de verdad
- Limpiarse entre ejecuciones

---

## 🧠 Enfoque del testing

Estos tests validan:

- Compatibilidad real con PostgreSQL
- Mapping JPA correcto
- Tipos de datos reales
- Transacciones reales

No deben:
- Duplicar tests unitarios
- Introducir lógica de negocio en tests

---

## ✅ Criterios de aceptación

El ejercicio se considera completado cuando:

- ✅ Los tests usan PostgreSQL real (no H2)
- ✅ Los tests pasan sin depender del entorno local
- ✅ El contenedor se levanta y destruye automáticamente
- ✅ No hay configuración “hardcodeada”
- ✅ Los tests siguen siendo reproducibles

---

## 🧠 Aprendizaje clave

> **Si funciona con Testcontainers y PostgreSQL real,  
> funcionará en producción.**

---

Este ejercicio cierra el ciclo completo:

- dominio
- aplicación

- web

- tests profesionales

Es un paso muy importante hacia **calidad de nivel senior**.
