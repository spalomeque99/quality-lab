# 📅 Día 11 — Tests de contrato (Application ↔ Infrastructure)

## 🎯 Objetivo
Aprender a **proteger los contratos de la capa application** mediante tests reutilizables, asegurando que **cualquier implementación de infraestructura cumple el comportamiento esperado**.

Este ejercicio introduce el concepto de:
- Tests de contrato
- Reutilización de tests
- Separación clara entre *qué* se espera y *cómo* se implementa

---

## 🧠 Contexto
En la capa `application` has definido el contrato:

- `TaskRepository`

Este contrato es utilizado por `TaskService` sin conocer:
- si los datos se guardan en memoria
- si se usan JPA, JDBC o cualquier otra tecnología

Por tanto, **todas las implementaciones de `TaskRepository` deben cumplir las mismas reglas**.

---

## 🧪 Ejercicio

### A) Test abstracto de contrato
Crea una clase de test **abstracta** que:

- No dependa de Spring
- No conozca ninguna implementación concreta
- Defina los tests que cualquier `TaskRepository` debe pasar

Esta clase debe:
- Declarar un método abstracto que devuelva un `TaskRepository`
- Contener los tests comunes del contrato

---

### B) Comportamientos que debe cubrir el contrato
El test de contrato debe verificar, como mínimo:

1. **Guardar una Task válida**
    - devuelve una `Task`
    - se le asigna un `id`
    - mantiene `title`, `done` y `createdAt`

2. **Buscar una Task existente por id**
    - devuelve `Optional.present`
    - los datos coinciden con lo guardado

3. **Buscar una Task inexistente**
    - devuelve `Optional.empty`

---

### C) Implementación del contrato para JPA
Crea una clase de test concreta que:

- Extienda el test abstracto de contrato
- Use `TaskRepositoryJpaAdapter`
- Use PostgreSQL con Testcontainers
- Proporcione la implementación concreta al test abstracto

---

## 🚫 Restricciones
❌ No duplicar tests entre implementaciones  
❌ No usar mocks  
❌ No probar lógica de negocio  
❌ No introducir dependencias de infraestructura en el contrato

---

## ✅ Criterios de aceptación
El ejercicio se considera completado cuando:

✅ Existe un test abstracto de contrato  
✅ El contrato se ejecuta contra la implementación JPA  
✅ No hay duplicación de tests  
✅ Los tests describen comportamiento, no implementación  
✅ `mvn test` pasa en verde

---

## 💡 Pista conceptual (sin solución)
> Si mañana cambias JPA por otra tecnología,  
> **solo deberías escribir una nueva clase de test que reutilice el contrato existente**.
